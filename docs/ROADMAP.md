# Namotai — План разработки (Roadmap)

**Версия:** 1.1
**Дата:** 2026-10-14
**Связанный документ:** Namotai — Design Document v0.3

---

## Обзор

Документ описывает этапы разработки MVP Namotai от bootstrap до запуска на VPS. Каждый этап содержит задачи, артефакты, критерии приёмки и оценку сроков.

**Общая оценка:** ~3–3,5 недели для одного разработчика (fullstack + AI).

**Принцип:** сначала работающий сквозной пайплайн, потом улучшения. Не оптимизировать то, что ещё не проверено. CI настраивается **до** первого функционального кода.

---

## Сводка этапов

| Этап | Название | Срок | Результат |
|---|---|---|---|
| 0 | Bootstrap проекта | 1–2 дня | Репозиторий, Docker, каркас API и UI |
| 0.5 | CI/CD на репозиторий | 1 день | Lint + test + build в GitHub Actions |
| 1 | Приём файла | 2–3 дня | Загрузка видео и текста, валидация |
| 2 | Транскрипция | 2–3 дня | Whisper → транскрипт с таймкодами |
| 3 | Парсинг текста | 1–2 дня | txt / docx / pdf → нормализованный текст |
| 4 | Генерация через LLM | 3–4 дня | Конспект + вопросы, контроль качества |
| 5 | Выдача результата и экспорт | 2–3 дня | GET результата, экспорт MD / PDF / JSON |
| 6 | Frontend | 4–5 дней | Две вкладки, форма, результат |
| 7 | Тестирование и деплой | 3–4 дня | E2E, VPS, nginx, мониторинг |

**Итого:** ~19–27 рабочих дней.

## Этап 0. Bootstrap проекта

**Срок:** 1–2 дня

### Задачи

1. Создать структуру репозитория
2. Настроить `docker-compose.yml` (api + postgres + nginx)
3. Backend: каркас FastAPI
   - `config.py` (Pydantic Settings)
   - `main.py` с `/health`
   - подключение к PostgreSQL
   - Alembic (пустые миграции)
4. Frontend: каркас Next.js
   - `create-next-app` с TypeScript и Tailwind
   - заглушка главной страницы
   - API-клиент
5. `.env.example`, `.gitignore`, `README.md`
6. Заглушки тестов (`test_health.py`)

### Артефакты

- Репозиторий `namotai/`
- `docker compose up` поднимает api и postgres
- `GET /health` → `{"api": "ok"}`
- Next.js заглушка на `localhost:3000`

### Критерии приёмки

- [ ] `docker compose up` работает без ошибок
- [ ] `/health` отвечает
- [ ] Frontend открывается
- [ ] Alembic видит пустую БД
- [ ] Секреты не в репозитории

## Этап 0.5. CI/CD на репозиторий

**Срок:** 1 день

**Цель:** настроить автоматическую проверку кода до появления первого функционального кода.

### Задачи

1. Создать `.github/workflows/backend.yml`
   - триггер: push / PR в `main` при изменениях в `backend/`
   - Python 3.12 + кэш `pip`
   - `ruff check` + `ruff format --check`
   - `pytest` с покрытием
2. Создать `.github/workflows/frontend.yml`
   - триггер: push / PR в `main` при изменениях в `frontend/`
   - Node 20 + кэш `npm`
   - `npm run lint`
   - `npm run build`
3. Настроить `pyproject.toml` (ruff + pytest)
4. Настроить `.eslintrc.json` (frontend)
5. Первый коммит со всеми файлами — CI должен пройти зелёным
6. Защита ветки `main`:
   - Require PR before merging
   - Require status checks: `backend`, `frontend`
   - Require branches up to date

### Артефакты

- Два рабочих workflow в GitHub Actions
- Зелёный CI на первом коммите
- Защита `main` включена

### Критерии приёмки

- [ ] CI запускается на push и PR
- [ ] Backend: lint + format + test проходят
- [ ] Frontend: lint + build проходят
- [ ] Кэш зависимостей работает (повторный запуск быстрее)
- [ ] Прямой push в `main` запрещён
- [ ] PR без зелёного CI не мержится

## Этап 1. Приём файла

**Срок:** 2–3 дня

### Задачи

1. Эндпоинт `POST /api/generate`
   - `multipart/form-data`
   - поля: `file` / `text`, `source_type`, `difficulty`, `question_count`
2. Валидация
   - размер файла ≤ 100 МБ
   - MIME и расширение
   - обязательность полей
3. Сохранение файла
   - `MEDIA_DIR/{uuid}/source.ext`
   - очистка в `finally`
4. Проверка длительности видео через `ffprobe` (≤ 2 часа)
5. Модель `results` в БД + миграция Alembic
6. Обработка ошибок: 413 / 422 / 500 с понятными сообщениями
7. Rate limit по IP (5 задач / сутки)
8. **Тесты:** юнит на валидацию, интеграционный на приём
9. **CI:** добавить шаги для новых зависимостей (если понадобится)

### Артефакты

- Эндпоинт принимает файл и возвращает `id`
- Запись в БД создаётся
- Файл удаляется после запроса

### Критерии приёмки

- [ ] Файл > 100 МБ → 413
- [ ] Невалидный формат → 422
- [ ] Видео > 2 часов → 422
- [ ] Успешный приём → 200 с `id`
- [ ] Временные файлы не остаются на диске
- [ ] Rate limit работает
- [ ] Тесты проходят в CI

## Этап 2. Транскрипция (видео)

**Срок:** 2–3 дня

### Задачи

1. Интеграция с Whisper (Cloud.ru)
   - `httpx.AsyncClient`
   - retry 2 раза при ошибке
   - таймаут
2. Извлечение аудио через ffmpeg
   - `-vn -ac 1 -ar 16000`
   - вывод в `audio.wav`
3. Пайплайн: видео → аудио → Whisper → сегменты
4. Сохранение сегментов `{start, end, text}` в `results.transcript`
5. Расчёт стоимости Whisper (длительность × 0.005 ₽)
6. Обработка ошибок: битое видео, нет аудиодорожки, таймаут
7. **Тесты:** мок Whisper, проверка расчёта стоимости
8. **CI:** добавить `ffmpeg` в шаги (если нужно)

### Артефакты

- Транскрипт с таймкодами в БД
- Стоимость Whisper записана
- Аудио и видео удалены после обработки

### Критерии приёмки

- [ ] 5-минутное видео → транскрипт за < 60 секунд
- [ ] Таймкоды присутствуют
- [ ] Стоимость рассчитана верно
- [ ] Ошибка Whisper → retry → понятное сообщение
- [ ] Временные файлы удалены
- [ ] Тесты проходят в CI

## Этап 3. Парсинг текста

**Срок:** 1–2 дня

### Задачи

1. Парсеры форматов
   - `txt` — чтение как есть
   - `docx` — `python-docx`
   - `pdf` — `pypdf` (без OCR)
2. Нормализация
   - удаление лишних пробелов и переносов
   - склейка разорванных предложений
3. Чанкинг для длинных текстов
   - разбивка по абзацам/разделам
   - сохранение `chunks` в `results.source_text`
4. Обработка ошибок: пустой файл, битый docx, PDF-скан
5. **Тесты:** юнит на каждый формат

### Артефакты

- Нормализованный текст в БД
- Чанки с индексами

### Критерии приёмки

- [ ] `txt` / `docx` / `pdf` парсятся
- [ ] PDF-скан → понятная ошибка (нет OCR)
- [ ] Длинный текст разбит на чанки
- [ ] Пустой файл → 422
- [ ] Тесты проходят в CI

## Этап 4. Генерация через LLM

**Срок:** 3–4 дня

### Задачи

1. Интеграция с DeepSeek V4 Flash (Cloud.ru)
   - `httpx.AsyncClient`
   - retry 2 раза
   - таймаут
2. Промпт-инжиниринг
   - системный промпт
   - инструкции по сложности
   - требования к JSON
   - запрет на шаблонность
3. Парсинг JSON-ответа
   - валидация схемы (Pydantic)
   - извлечение `summary` и `questions`
4. Контроль качества
   - проверка количества вопросов
   - проверка 4 опций для `single_choice`
   - проверка дубликатов
   - проверка `source_ref`
   - повторный запрос при провале
5. Расчёт стоимости LLM (токены × тариф)
6. Сохранение в `results`
7. **Тесты:** мок LLM, проверка парсинга и контроля качества

### Артефакты

- Конспект + вопросы в БД
- Стоимость LLM записана
- Логирование токенов

### Критерии приёмки

- [ ] 5–10 вопросов генерируются
- [ ] JSON валиден
- [ ] Сложность влияет на вопросы
- [ ] Дубликатов нет
- [ ] `source_ref` попадает в диапазон
- [ ] Стоимость рассчитана верно
- [ ] Ошибка LLM → retry → понятное сообщение
- [ ] Тесты проходят в CI

## Этап 5. Выдача результата и экспорт

**Срок:** 2–3 дня

### Задачи

1. `GET /api/results/{id}` — возврат результата
2. Экспорт
   - `GET /api/results/{id}/export?format=md`
   - `GET /api/results/{id}/export?format=json`
   - `GET /api/results/{id}/export?format=pdf`
3. PDF-генерация
   - библиотека (`weasyprint` или `reportlab`)
   - шаблон с конспектом и вопросами
4. Форматирование Markdown
   - заголовки, списки, блоки ответов
5. Обработка ошибок: результат не найден, формат не поддержан
6. **Тесты:** юнит на каждый формат экспорта

### Артефакты

- Рабочий GET результата
- Три формата экспорта

### Критерии приёмки

- [ ] `GET /api/results/{id}` возвращает полный результат
- [ ] MD-экспорт читаемый
- [ ] PDF-экспорт открывается
- [ ] JSON-экспорт валиден
- [ ] Несуществующий ID → 404
- [ ] Тесты проходят в CI

## Этап 6. Frontend

**Срок:** 4–5 дней

### Задачи

1. Главная страница `/`
   - две вкладки: «Видео» / «Текст»
   - drag&drop для файлов
   - textarea для текста
   - выбор сложности (радио)
   - слайдер количества вопросов
   - кнопка «Обработать»
2. Состояние загрузки
   - спиннер
   - текст «Обычно занимает 1–3 минуты»
   - предупреждение «Не закрывайте вкладку»
3. Страница результата `/results/{id}`
   - блок «Конспект»
   - список вопросов
   - сворачиваемые ответы
   - ссылка на таймкод (для видео)
   - кнопки экспорта
4. Обработка ошибок
   - 413, 422, 500 → понятные сообщения
   - кнопка «Попробовать снова»
5. Адаптивность (мобильные)
6. Стилизация Tailwind
7. **Тесты:** базовые (опционально, если добавим Vitest)

### Артефакты

- Рабочий UI с двумя вкладками
- Страница результата с экспортом

### Критерии приёмки

- [ ] Видео загружается через drag&drop
- [ ] Текст вставляется или загружается файлом
- [ ] Выбор сложности и количества работает
- [ ] Спиннер отображается во время обработки
- [ ] Результат отображается корректно
- [ ] Экспорт работает из UI
- [ ] Ошибки понятны пользователю
- [ ] Мобильная версия не ломается
- [ ] CI (lint + build) проходит

## Этап 7. Тестирование и деплой

**Срок:** 3–4 дня

### Задачи

1. Тесты
   - юнит: парсинг, чанкинг, расчёт стоимости
   - интеграционные: полный пайплайн на тестовом видео
   - E2E: загрузка → результат → экспорт
2. Docker
   - финальные Dockerfile для api и frontend
   - multi-stage сборка
   - оптимизация размера образа
3. **CD на VPS** (добавляется сюда)
   - GitHub Secrets: `SSH_HOST`, `SSH_USER`, `SSH_KEY`
   - workflow `deploy.yml`:
     - триггер: push в `main` после зелёного CI
     - SSH на VPS → `git pull` → `docker compose up -d --build`
   - или сборка образов в GitHub Container Registry + pull на VPS
4. VPS
   - установка Docker
   - nginx с `proxy_read_timeout 600s`
   - HTTPS (Let's Encrypt)
   - домен
5. Мониторинг
   - логи (stdout + файлы)
   - Sentry (опционально)
   - счётчик расходов
6. Rate limit на nginx
7. Бэкапы PostgreSQL

### Артефакты

- Работающий сервис на домене
- HTTPS
- Логи и мониторинг
- Автодеплой по push в `main`

### Критерии приёмки

- [ ] Все тесты проходят
- [ ] Сервис доступен по HTTPS
- [ ] Таймаут nginx 600s
- [ ] Rate limit работает
- [ ] Логи пишутся
- [ ] Бэкапы настроены
- [ ] E2E: видео 10 мин → результат за < 3 мин
- [ ] Push в `main` → автодеплой на VPS
- [ ] Откат при падении деплоя

## Что НЕ входит в MVP

| Фича | Когда |
|---|---|
| Celery + Redis | Когда HTTP-таймауты станут проблемой |
| Прогресс по этапам | Когда пользователи попросят |
| Аккаунты и история | Когда будет аудитория |
| OCR сканов | Когда понадобится |
| Английский интерфейс | После первых пользователей |
| Приём ссылок (YouTube) | Отдельный этап, требует юр. проработки |
| Интерактивное прохождение | После валидации идеи |
| API для LMS | После B2C-валидации |

## Риски и митигации

| Риск | Вероятность | Митигация |
|---|---|---|
| Whisper медленный на длинных видео | Средняя | Лимит 2 часа, тест на 1-часовом видео заранее |
| LLM выдаёт невалидный JSON | Высокая | Retry + строгая валидация + fallback-промпт |
| Качество вопросов низкое | Средняя | Итерации по промпту, сбор фидбэка, few-shot примеры |
| Долгий HTTP-запрос падает | Средняя | Таймаут nginx 600s, тест на 2-часовом видео |
| PDF-парсинг ломается на сканах | Высокая | Понятная ошибка, OCR вне MVP |
| Стоимость превышает ожидания | Средняя | Логирование каждой задачи, лимиты, мониторинг |
| Cloud.ru API недоступен | Низкая | Retry, понятная ошибка, статус-страница |
| CI падает на новых зависимостях | Средняя | Кэш, фиксация версий, локальный прогон перед push |

## Порядок работы

**Спринт 0 (день 1–3):** этапы 0, 0.5
**Спринт 1 (неделя 1):** этапы 1, 2
**Спринт 2 (неделя 2):** этапы 3, 4, 5
**Спринт 3 (неделя 3):** этапы 6, 7

**После каждого этапа:** запуск, проверка критериев приёмки, зелёный CI, коммит.

---

## Definition of Done для MVP

- [ ] Пользователь загружает видео или текст
- [ ] Получает конспект и 5–10 вопросов разной сложности
- [ ] Может экспортировать в MD / PDF / JSON
- [ ] Ошибки обрабатываются понятно
- [ ] Сервис работает на VPS по HTTPS
- [ ] Стоимость каждой задачи логируется
- [ ] Rate limit защищает от злоупотреблений
- [ ] E2E-тест проходит на видео 10 минут
- [ ] CI зелёный на каждом коммите
- [ ] Автодеплой работает
